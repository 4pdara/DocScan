# יומן מחקר 0.1.4 — מסננים, Android ו־Frida

## שאלות פתוחות

1. האם חמשת מסלולי ה־JNI שבדקנו ב־Unidbg עובדים גם בתוך Android, כולל Bitmap/אלפא ומקורות?
2. אילו קריאות Java ו־JNI מתרחשות בפועל, ומהם הפרמטרים וקודי ההחזרה?
3. האם אפשר להגיע להרצת CamScanner המקורית ולתעד את תהליך האתחול החוקי שלה?
4. מה חסר כדי לשלב Gray/Lighten/B&W/Eco דרך ScannerEngine, והאם קיימות תלויות שרת/מודל?

## תשתית חדשה

- Frida 17.26.0 מ־5 בנובמבר 2026 מאומתת מול הפרסום הרשמי והנכס הרשמי. פורסמו תיקונים ל־emulated realm ולמציאת exports ב־native bridge.
- שרת android-x86_64: SHA256 `5507894927e23837d4099bcbfa026e9d227bfc47544a115971fd1a358fba7437`.
- Android 11 Google APIs x86_64 עם KVM ב־GitHub Actions, במקום להסתמך רק על אמולציית תוכנה מקומית ללא KVM.
- הופרדו observers: Java/ART בסביבה המארחת; JNI ARM64 ב־realm=emulated. ערכי String מושחרים, אין חשבונות או סריקות משתמש בבדיקה.
- בדיקת Android כוללת השהיה אופציונלית לפני המסננים לצורך חיבור Frida. ברירת המחדל ללא השהיה. נבדקות תמונה סינתטית 96×128, שמירת ממדים/אלפא/שינוי פיקסלים ושמירת מקור.
- ספריות הבדיקה נחלצות באופן זמני מ־APK DocScan Native 0.1.3 שכבר פורסם, עם אימות SHA. הן אינן נכתבות לעץ המקור. מפתח מעבדה זמני שונה ממפתח ה־APK המופץ.

## הבחנות מחייבות

בדיקת המנוע בתוך DocScan אינה הרצת CamScanner עצמה. תצפית JNI גולמית אינה טיפוס החזרה מוכח; הטיפוסים וקודי ההחזרה נלקחים מהתצפית Java. אין שינוי בערכי החזרה, עקיפת רישוי, בדיקות אימות או מפתחות.

מיפוי כל 11 מסנני הממשק ונתיבי הקריאה נמצא ב־FILTER_CATALOG_HE.md. מסלולי SmartErase/TianShu תלויים בשרת; Gray/Lighten/B&W/Eco דורשים אתחול ScannerEngine תקין שטרם הושג. אין להפוך שמות בממשק לטענה שהיכולת פועלת.

## תוצאות

ממתינות לריצת המעבדה. כישלון חיבור/אמולטור יישמר כמגבלה עם הלוג המדויק, ולא יוצג כהצלחה. לא בוצעה בדיקה בטלפון אמיתי במסגרת גרסה זו.
