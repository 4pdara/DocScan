# התנהגות סריקה בסרטוני Google Drive

נבדקו שני הסרטונים שסיפק המשתמש: סרטון של כ־20 שניות המציג רצף סריקה, וסרטון הדרכה בעברית באורך כ־130 שניות. נבדק הרצף החזותי לאורך הסרטונים ונפתחו פריימים מפורטים בנקודות מפתח. הסרטונים, צילומי המסך ופרטי החשבונות שבהם אינם מועתקים למאגר.

| התנהגות שנראית בסרטון | התאמה ל־DocScan |
| --- | --- |
| צילום אוטומטי, מסגרת וחיווי שמירה לאורך הרצף הקצר | שיפור הזיהוי וחלון יציבות קצר יותר, תוך שמירת מניעת כפילויות |
| תמונות ממוזערות שמצטברות במהלך הסריקה | פס עמודים במצלמה עם גישה לעורך וחזרה |
| שתי מסגרות דפים באותו פריים בסרטון הקצר | דרישה נפרדת לזיהוי כמה דפים; טרם ממומשת |
| תצוגת עמודים, הוספת עמוד וכפתור צילום מחדש בסרטון הארוך | תצוגת המסמך והוספת עמודים נשמרו; נוספה החלפת צילום לעמוד נבחר |
| מסך חיתוך עם פינות, סיבוב, זיהוי אוטומטי וללא חיתוך, בערך בשניות 42–51 | כבר קיימים חיתוך חוזר, זיהוי חוזר, איפוס וסיבוב |
| כלי סינון וכפתור ניקוי בתצוגת העריכה | נוספו ניקוי רקע ושיפור טקסט עם עוצמה. הסרטון אינו מדגים את פעולת כלי הניקוי עצמו, ואין להסיק ממנו את האלגוריתם |
| בחירת PDF או JPEG ושם קובץ, בערך בשניות 63–81 | PDF ושמות מסמכים קיימים; נוסף ייצוא עמודי JPEG לתיקייה נבחרת |
| שיתוף באמצעות תפריט Android בהמשך הסרטון | שיתוף PDF דרך Android כבר קיים |

## מנוע הסריקה

הסרטונים מדגימים התנהגות ותוצאה, ולא את המימוש הפנימי. לפי [התיעוד הרשמי של Google ל־ML Kit Document Scanner](https://developers.google.com/ml-kit/vision/doc-scanner/android), המודלים, לוגיקת הסריקה והממשק של ה־SDK יורדים דרך Google Play services. הוא מספק זרימת סריקה ומחזיר PDF ו־JPEG. זהו רכיב רשמי שאפשר לבחון; אין במסמך הזה הוכחה שגרסת Drive המצולמת משתמשת בדיוק בו או באותה גרסת מנוע.

אם יימסר APK, נבדוק את החבילה המקורית ורכיביה, לרבות ספריות Native, תלויות ומודולים דינמיים. Decompile יכול לסייע במיפוי החיבורים, אך אינו מבטיח שחזור מודלים או אלגוריתם שאינו כלול בחבילה. אין צורך לשנות או לפרק את קובץ המקור לפני מסירתו לבדיקה.
